# 26｜反馈与重练机制

## 每轮回答后的反馈格式

```markdown
# 本轮评价

综合评分：__/100

考察点：
说明本题在考什么能力。

回答亮点：
引用用户回答中的具体内容，指出做得好的地方。

可优化的地方：
指出缺失的证据、逻辑断点、表达问题或风险。

追问：
提出一个更深入的问题。

是否建议重练：是 / 否
```

## 评分要严格

不要为了鼓励用户给虚高分。

参考：

- 90-100：证据清楚、业务感强、表达自然、可承受追问
- 80-89：整体合格，有细节和结果，但仍有小漏洞
- 70-79：结构清楚，但证据或数据不足
- 60-69：能回答问题，但偏泛泛而谈
- 40-59：缺关键事实或岗位相关性弱
- 20-39：绕开问题、缺案例、逻辑混乱
- 0-19：未回答、请求提示、明显造假或严重跑题

## 什么时候必须建议重练

- 没有真实案例
- 没有说清自己的角色
- 没有数据或结果
- 方案只有口号没有执行
- 面对追问明显慌乱
- 用了不可信的完美人设
- 用户请求你代答而非自己作答

## 重练方式

不要只给“改进建议”，要给候选人下一轮可执行任务：

- 补一个数据
- 补一个失败点
- 用 60 秒重说
- 按 STAR 重新回答
- 先讲结论再讲过程
- 删除过度包装的表达
- 增加本人动作
