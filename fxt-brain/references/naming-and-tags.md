## 文件命名规范

### 基本规则

```
格式：YYYYMMDD-简明标题.md
示例：20260526-MySQL索引优化笔记.md
```

| 规则 | 说明 | 好的 | 不好的 |
|------|------|------|--------|
| 日期前缀 | 8位日期，方便排序 | `20260526-xxx.md` | `5月26日-xxx.md` |
| 分隔符 | 用 `-` 不用 `_` 和空格 | `MySQL-索引.md` | `MySQL_索引.md` |
| 标题长度 | ≤40个中文字 | `分布式事务两阶段提交.md` | `关于分布式事务的两阶段提交协议的一些理解和总结.md` |
| 英文大小写 | 专有名词保留大小写 | `MySQL` `React` `API` | `mysql` `REACT` |
| 特殊字符 | 不用 `/\:*?"<>|` | — | — |

### 不同类型文件的前缀

| 文件类型 | 前缀 | 示例 |
|---------|------|------|
| 通用笔记 | 日期 | `20260526-MySQL索引.md` |
| 知识卡片 | `KC-` | `KC-数据库索引原理.md` |
| 内容地图(MOC) | 无前缀，放在 MOC 文件夹 | `分布式系统.md` |
| 读书笔记 | 书名开头 | `《深入浅出现代Web编程》-第3章.md` |
| 会议记录 | `MTG-` | `MTG-20260526-周会.md` |
| 项目笔记 | 项目名- | `搜索重构-技术方案.md` |

## 标签体系

### 标签分类

一个好的标签体系应该覆盖三个维度：**是什么领域、是什么类型、处于什么状态**。

#### 领域标签（主题相关）

```
#技术 #产品 #设计 #商业 #管理
#心理学 #哲学 #历史 #经济学 #社会学
#写作 #营销 #数据 #投资 #法律
#教育 #医学 #艺术 #音乐 #摄影
```

#### 类型标签（笔记性质）

| 标签 | 含义 | 使用场景 |
|------|------|---------|
| #笔记 | 学习笔记 | 读书/上课/看文章后的归纳 |
| #摘抄 | 原文摘录 | 值得记住的原话 |
| #思考 | 自己产生的想法 | 灵感、反思、独立观点 |
| #实践 | 实操记录 | 自己动手做过的记录 |
| #问题 | 待解决的问题 | 记录困惑，后续检索答案 |
| #总结 | 周期性总结 | 周报、月总结、项目复盘 |
| #决策 | 决策记录 | 为什么选A不选B，背景和依据 |

#### 状态标签（处理进度）

| 标签 | 含义 |
|------|------|
| #草稿 | 快速记录，还没整理 |
| #待整理 | 有内容但结构混乱 |
| #已完成 | 结构完整，可对外分享 |
| #待补充 | 核心内容有了，缺一些细节 |
| #过时 | 信息已过时，保留仅供参考 |

### 打标签原则

1. **每篇 2-4 个标签**，最少 1 个领域 + 1 个类型，最多不超 5 个
2. **不打太细的标签**：`#技术` 足够，不需要 `#技术-后端-数据库-MySQL-索引`
3. **不打太泛的标签**：`#学习` 太泛，应该按领域细化
4. **保持一致**：一旦用了 `#技术`，不要另用 `#科技` 表示同一个意思
5. **标签要检索过**：打标签前问自己：我以后会按这个标签搜索吗？

## 最佳实践

### 1. 收件箱是第一关

所有新笔记先扔进 `0-收件箱/`，不要直接在领域文件夹里新建。每天或每周花 10 分钟整理收件箱——归类、打标签、改名。这能避免「每次都要决定放哪」的决策负担。

### 2. 笔记要「可检索」

- 标题写好：`MySQL索引优化` 比 `数据库笔记` 更容易被搜到
- 正文前 200 字要包含关键信息（搜索时最依赖开头）
- 同义词在正文中也提一下：比如写了「索引」，也提一嘴「index」

### 3. 定期「除草」

每月花 30 分钟：
- 删除明显过时的笔记
- 合并内容高度重复的笔记
- 更新标签不一致的笔记
- 把草稿要么完善要么删掉

### 4. 不求完美

- 一篇笔记 200 字就够，不需要洋洋洒洒
- 标签不准没关系，后续可以改
- 先有框架再慢慢完善，不要一开始就想设计完美体系
- 知识库的价值在于「积累」，不在「架构建得漂亮」
