# 5 套知识库目录结构模板

---

## 模板 1：PARA 法

**最适合**：同时推进多个项目的人（职场人士、自由职业者）

**核心逻辑**：按「可操作性」分级，越常用的离根目录越近

```
知识库/
├── 0-收件箱/              # 快速捕获，未整理的临时存放
├── 1-项目/                # 正在推进的项目（有截止日期+有明确产出）
│   ├── Q2绩效评估/
│   ├── 新功能开发-搜索/
│   └── 团队分享-5月份/
├── 2-领域/                # 长期负责的领域（持续关注，无截止日期）
│   ├── 技术-后端/
│   ├── 产品思维/
│   └── 团队管理/
├── 3-资源/                # 感兴趣但非当前的参考材料
│   ├── 感兴趣的文章/
│   ├── 设计灵感/
│   └── 工具清单/
├── 4-归档/                # 已完成或不再活跃的项目/领域
└── 模板/                  # 笔记模板
```

**使用节奏**：
- 每天：打开收件箱，花 10 分钟归类到项目/领域/资源
- 每周：回顾项目文件夹，把已完成的移到归档
- 每月：回顾领域文件夹，看是否需要新建或拆分

## 模板 2：MOC 法（内容地图法）

**最适合**：深度研究者、需要大量写作输出的人

**核心逻辑**：每个主题一个 MOC（Map of Content）+ 链接形式聚合相关笔记，逐步形成树状结构

```
知识库/
├── 0-MOC/                 # 内容地图（每个大主题一个 MOC 文件）
│   ├── 分布式系统.md      # MOC：概述+链接到所有相关笔记
│   ├── 认知心理学.md
│   └── 写作方法论.md
├── 1-笔记/                # 所有笔记按子主题放在文件夹里
│   ├── 分布式系统/
│   │   ├── 一致性算法.md
│   │   ├── CAP定理.md
│   │   └── 分布式事务.md
│   ├── 认知心理学/
│   └── 写作方法论/
├── 2-来源/                # 原文摘抄、读书笔记
├── 3-日常/                # 日记、周报、零散思考
└── 模板/
```

**使用节奏**：
- 写完一篇新笔记后 → 在对应的 MOC 文件中加一行链接 + 一句话摘要
- MOC 超过 50 个链接 → 拆分成子 MOC
- 发现两个 MOC 有大量交叉 → 考虑合并或建立交叉链接

## 模板 3：时间轴法

**最适合**：日记/复盘型、需要追踪个人成长的人

**核心逻辑**：按时间自然组织，适合「记录 + 回顾」的使用习惯

```
知识库/
├── 日记/                  # 日常记录
│   ├── 2026/
│   │   ├── 05/
│   │   │   ├── 2026-05-26.md
│   │   │   └── 2026-05-25.md
│   │   └── 04/
│   └── 2025/
├── 周复盘/
│   ├── 2026-W21.md
│   └── 2026-W20.md
├── 月总结/
│   ├── 2026-05.md
│   └── 2026-04.md
├── 年度/
│   ├── 2026-年度目标.md
│   └── 2026-年度总结.md
├── 主题笔记/              # 不局限于某一天的专题笔记
│   ├── 读书/
│   └── 项目/
└── 模板/
```

**使用节奏**：
- 每天：写日记（5分钟，记录 3 件事 + 1 个思考）
- 每周：写周复盘（对照周目标，列完成/未完成/下周计划）
- 每月：写月总结（回顾本月成长的 3 件事 + 下月重点）

## 模板 4：来源驱动法

**最适合**：大量阅读输入型（书虫、课虫、信息消费者）

**核心逻辑**：按信息来源分类，方便追溯

```
知识库/
├── 书籍/
│   ├── 《书名1》/
│   │   ├── 00-总览.md
│   │   ├── 01-第1章笔记.md
│   │   └── 02-第2章笔记.md
│   └── 《书名2》/
├── 课程/
│   ├── 课程A/
│   └── 课程B/
├── 文章/
│   ├── 已读/
│   │   └── 2026-05-26-《文章标题》.md
│   └── 待读清单.md
├── 播客/
├── 视频/
├── 会议/报告/
├── 自己写的/
│   ├── 想法碎片/
│   └── 成文/
└── 模板/
```

**使用节奏**：
- 每天：读 1 篇文章，做 1 篇笔记
- 每周：清理待读清单，完成 1 篇课程笔记
- 每本书读完后：写一篇总览（写这本书改变了我哪个观点 + 我会马上做哪件事）

## 模板 5：Zettelkasten（卡片盒法）

**最适合**：创意输出型、写作者、需要连接想法的人

**核心逻辑**：每张卡片只记一个想法，用双向链接串联成网络

```
知识库/
├── 卡片/                  # 原子化笔记
│   ├── 2026-05-26-数据库索引就像书的目录.md
│   ├── 2026-05-25-函数式编程的核心是数据不可变.md
│   └── 2026-05-24-好的设计是减少用户的选择成本.md
├── 索引/                  # 主题索引（类似 MOC 但更轻量）
│   ├── 编程范式.md         # 列出相关卡片链接
│   ├── 设计原则.md
│   └── 学习方法.md
├── 来源/                  # 阅读来源的原始笔记
├── 草稿/                  # 正在形成的文章/观点
└── 模板/
```

**三条铁规**：
1. **一张卡片只记一个想法** — 如果写完发现有两个独立观点，拆成两张
2. **用自己的话写** — 不复制粘贴，必须用自己的话转述
3. **一定要加链接** — 每张卡片至少链接到 1 张已有卡片

**使用节奏**：
- 每天：写 3-5 张卡片（在读文章/思考/讨论中捕获想法）
- 每周：回顾最近的卡片，发现「卡片簇」（一个主题相关 5+ 张卡片）→ 写一篇索引
- 每月：检查哪些索引下的卡片特别丰富 → 考虑写成一篇完整文章

## 怎么选？

| 你的情况 | 推荐模板 |
|---------|---------|
| 同时干好几个项目，经常切换上下文 | PARA 法 |
| 某个领域想深入，需要写大量输出 | MOC 法 |
| 主要写日记/复盘，记录个人成长 | 时间轴法 |
| 大量读书/上课，输入特别多 | 来源驱动法 |
| 经常写文章，想连接各种想法产生新创意 | Zettelkasten |

**不确定就先选 PARA。** PARA 最通用，后续可以按需演化到其他方式。
