# 知识库搭建技能

## 它做什么

不让你装任何新软件，不让你把数据上传到任何云端。用你电脑上已有的文件夹和 Markdown 文件，搭建一套**结构化、可检索、可持续积累**的本地知识库。

四个核心场景：

| 场景 | 你只需说 | 输出 |
|------|---------|------|
| 搭建知识库 | 我主要学/写什么领域 | 目录结构 + 命名规范 + 一篇 README 说明 |
| 整理已有资料 | 我的笔记大概在哪几个文件夹 | 分类方案 + 标签体系 + 逐文件迁移计划 |
| 提取归纳 | 扔一篇文章/一段笔记过来 | 结构化知识卡片（核心观点+关键论据+行动启发） |
| 检索查询 | 想找关于某主题的内容 | 跨文件关键词检索 + 关联推荐 |

---

## 核心原则

这是一条**硬规则**：

**数据 100% 留在本地。** 不推荐任何需要上传到云端的工具。所有方案基于本地文件夹 + Markdown 文件。如果需要截图 OCR，优先用本地工具（如 PowerToys Text Extractor），不推荐在线 OCR 服务。

---

## 入口引导

当用户进入此技能时：

> 你想做什么？
> 1. **从零搭建知识库** — 我还没开始，想先搭个框架
> 2. **整理已有资料** — 我电脑里已经有很多笔记/文档，太乱了想整理
> 3. **提取归纳** — 我这有篇文章/一段笔记，帮我提炼成知识卡片
> 4. **检索查询** — 帮我从知识库里找某个主题的内容

如果用户已经说得很清楚，直接进入对应流程。

## 场景一 · 从零搭建知识库

> 触发：用户说"想搭个知识库"、"怎么做知识管理"、"第二大脑怎么建"等。

### 必收集信息

- **核心领域**：你主要学什么/做什么？（技术开发/产品设计/学术研究/投资理财/写作创作/综合）
- **使用习惯**：主力设备（Mac/Win/双平台）+ 用什么编辑器（VS Code/Obsidian/Typora/记事本）
- **规模预期**：预计一年积累多少篇笔记？（<100 / 100-500 / >500）

### 目录结构模板

根据用户领域推荐最合适的模板（共 5 套，详见 `references/directory-templates.md`）：

| 模板 | 适合人群 | 核心逻辑 |
|------|---------|---------|
| **PARA 法** | 多项目并行的人 | 按「项目/领域/资源/归档」四分 |
| **MOC 法** | 深度研究者 | 每个主题一个 MOC（内容地图），笔记按主题聚合 |
| **时间轴法** | 日记/复盘型 | 按年/月/日组织，适合日记+定期复盘 |
| **来源驱动法** | 大量阅读输入型 | 按「书籍/文章/课程/播客/会议」分类 |
| **Zettelkasten** | 创意输出型 | 原子化笔记 + 双向链接，每条笔记只记一个想法 |

### 输出模板

```markdown
## 知识库搭建方案

### 基本信息
- **领域**：{领域}
- **模板**：{选中的模板名}
- **编辑器**：{编辑器}

### 目录结构

​```
知识库/
├── README.md              # 知识库说明 + 使用约定
├── 0-收件箱/              # 临时存放，待整理的笔记
├── 1-项目/                # 进行中的项目相关笔记
│   ├── 项目A/
│   └── 项目B/
├── 2-领域/                # 长期关注的领域知识
│   ├── 技术/
│   ├── 产品/
│   └── 写作/
├── 3-资源/                # 感兴趣但非当前重点
├── 4-归档/                # 已完成/不再维护
└── 模板/                  # 笔记模板
​```

### 命名规范

- **文件夹**：`领域-子领域`，如 `技术-后端-数据库`
- **笔记文件**：`YYYYMMDD-标题.md`，如 `20260526-MySQL索引优化笔记.md`
- **知识卡片**：`KC-{主题}.md`，如 `KC-数据库索引原理.md`
- **不允许**：空格用 `-` 代替，不用 `_`，不用大写字母开头（英文除外）

### 标签体系

建议从以下标签开始（每篇笔记打 2-4 个）：

| 标签类型 | 示例 | 格式 |
|---------|------|------|
| 领域标签 | #技术 #产品 #商业 | 用中文 |
| 类型标签 | #笔记 #文章摘要 #思考 #实践 | 用中文 |
| 状态标签 | #草稿 #待整理 #已完成 | 用中文 |

### 笔记模板

每篇笔记建议包含以下元数据（YAML frontmatter）：

​```yaml
---
title: "笔记标题"
date: 2026-05-26
tags: [技术, 数据库, 笔记]
status: 已完成
source: "《高性能MySQL》第3章"
---
​```

### 马上可以做的

1. 在 {建议路径} 创建上述目录结构
2. 把 README.md 写好（写清楚这个知识库的用途和使用约定）
3. 创建第一个模板文件放在「模板」目录下
4. 从「收件箱」开始，先把你最近一周的零散笔记扔进去
```

### ⚠️ 输出检查点

生成搭建方案后暂停：

> 知识库框架已设计好，请确认：
> 1. 目录结构符合你的使用习惯吗？需要增减哪些文件夹？
> 2. 推荐的模板（{模板名}）合适吗？看看另外几套要不要换？
> 3. 命名规范和标签体系清楚吗？有没覆盖到的重要领域标签？
>
> 确认后我把这套目录结构建起来。

## 场景二 · 整理已有资料

> 触发：用户说"整理笔记"、"资料太乱了"、"帮我分类"等。

### 必收集信息

- **资料在哪**：哪几个文件夹里散落着笔记？（给路径）
- **大概多少**：几十篇还是几百篇？
- **主要类型**：文章摘抄/读书笔记/工作记录/学习笔记/截图/PDF？

### 处理流程

```
Step 1: 扫描文件
  列出所有笔记文件的路径、大小、修改时间

Step 2: 内容分类
  逐文件快速阅读（前200字 + 标题），提出分类建议：
  - 应该归到哪个领域文件夹
  - 应该打什么标签
  - 哪些是重复/过时可以删的

Step 3: 生成迁移计划
  输出一张迁移清单：
  | 文件 | 当前位置 | 建议移动到 | 建议标签 | 备注 |

Step 4: 等确认后执行
  用户确认分类方案后，逐文件执行移动/重命名/添加frontmatter
```

### 输出模板

```markdown
## 资料整理方案

### 扫描结果
- **总文件数**：{N} 个
- **总大小**：{大小}
- **跨度**：{最早日期} ~ {最晚日期}
- **主要类型分布**：{分布}

### 建议分类结构

​```
知识库/
├── ...
├── 2-领域/
│   ├── {领域1}/    ← {N}篇相关
│   ├── {领域2}/    ← {M}篇相关
│   └── {领域3}/    ← {K}篇相关
└── 4-归档/         ← {X}篇过时/重复
​```

### 迁移清单（前 20 条）

| # | 文件名 | 当前位置 | 建议位置 | 建议标签 | 操作 |
|---|--------|---------|---------|---------|------|
| 1 | xxx.md | ./杂/ | 2-领域/技术/ | #技术 #笔记 | 移动+改名 |
| ... | ... | ... | ... | ... | ... |

### 可删除/归档（{X} 个文件）

| 文件名 | 原因 |
|--------|------|
| xxx.md | 与 yyy.md 内容重复 |
| zzz.md | 2022年的过时信息 |

> 以上方案确认后，我帮你自动执行移动和重命名。需要先确认吗？
```

### ⚠️ 输出检查点

输出迁移清单后暂停：

> 整理方案已生成，请确认：
> 1. 分类结构合理吗？有没有分错领域的文件？
> 2. 标记为「可删除/归档」的文件确认可以处理吗？
> 3. 要不要先挑 5 篇试迁移，看看效果再全量执行？
>
> 确认后按清单执行迁移。

## 场景三 · 提取归纳（知识卡片）

> 触发：用户粘贴一篇文章、一段笔记、一篇摘抄，或说"帮我提炼"、"总结一下"、"做成知识卡片"等。

### 处理步骤

1. **阅读全文**，识别文章类型：观点论述 / 教程实践 / 信息罗列 / 故事叙述
2. **提取核心**：用「一句话总结 + 三个关键点 + 一个行动启发」格式
3. **生成知识卡片**：包含结构化摘要 + 标签建议 + 关联推荐
4. **等用户确认后保存**为独立 Markdown 文件

### 知识卡片模板

```markdown
---
title: "{知识卡片标题}"
date: {日期}
tags: [{标签1}, {标签2}, {标签3}]
status: 已完成
source: "{来源文章标题或URL}"
type: 知识卡片
---

# {标题}

## 一句话总结
{用一句话讲清楚这篇文章/这段笔记的核心观点或价值}

## 三个关键点
1. **{要点1}** — {1-2句说明}
2. **{要点2}** — {1-2句说明}
3. **{要点3}** — {1-2句说明}

## 原文精华摘录
> {最值得记住的原句，不超过3条}

## 我的思考
{这篇文章和你已有认知的连接点、不同看法、待验证的疑问}

## 行动启发
- [ ] {看完这篇文章后，可以做的具体一件事}
```

### ⚠️ 输出检查点

知识卡片生成后暂停：

> 知识卡片已生成，请确认：
> 1. 一句话总结准确吗？有没有曲解原意？
> 2. 三个关键点是你最关心的角度吗？
> 3. 要不要补充「我的思考」部分再保存？
>
> 确认后保存为 `KC-{标题}.md`。

## 场景四 · 检索查询

> 触发：用户说"帮我找一下"、"有没有关于 X 的笔记"、"知识库里关于 X 有什么"等。

### 处理步骤

1. **确认检索范围**：指定文件夹还是全知识库？
2. **关键词搜索**：跨文件正文搜索，列出所有匹配的文件和片段
3. **关联推荐**：除了直接匹配，还推荐标签相近、主题相关的其他笔记
4. **输出检索报告**

### 输出模板

```markdown
## 检索结果：「{检索词}」

### 直接匹配（{N} 篇）
| # | 文件 | 匹配片段 | 标签 |
|---|------|---------|------|
| 1 | {文件名} | {匹配的前50字}... | #标签 |
| 2 | {文件名} | {匹配的前50字}... | #标签 |

### 相关推荐
以下笔记虽然没有直接包含「{检索词}」，但标签/主题相关：
| # | 文件 | 标签 | 关联原因 |
|---|------|------|---------|
| 1 | {文件名} | #标签 | 同属「{领域}」 |

### 知识缺口
根据你的标签分布，这些相关主题目前还没有笔记：
- {主题1}
- {主题2}
```

### ⚠️ 输出检查点

输出检索结果后暂停：

> 检索完成，请确认：
> 1. 这些是你想找的内容吗？要不要缩小/扩大检索范围？
> 2. 「知识缺口」里有你现在想了解的主题吗？可以帮你收集整理。
> 3. 需要深入阅读匹配到的哪几篇笔记吗？
>
> 确认检索方向后再继续。

## 交互总则

1. **数据在本地**：不推荐任何云端笔记工具，方案全部基于本地文件夹 + Markdown
2. **先看再动**：整理前先扫描、先出方案，用户确认后再执行文件操作
3. **可逆操作**：整理时优先「复制到知识库」而非「移动」，等用户确认无误后再提示可以删除原文件
4. **保持简单**：不引入数据库、不装软件、不用复杂工具。文件夹 + Markdown + 一个好用的编辑器就够了
5. **渐进整理**：不要求一次性整理完。支持「每天整理 10 篇」的节奏
6. **一个主题一个文件**：知识卡片保存到知识库的对应领域文件夹

## 边界条件处理

### 输入不足：先拒后问

| 场景 | 最低标准 | 不达标时追问 |
|------|---------|------------|
| 搭建知识库 | 至少知道主要领域 | "你主要关注哪几个领域？比如主要是学技术，还是做投资研究，还是综合性的？这决定了用什么目录结构。" |
| 整理资料 | 至少给出一个文件夹路径 | "你的笔记大概在哪个文件夹？给我一个路径，我先扫描看看。" |
| 提取归纳 | 至少一段文字（>50字） | "发一段文字给我，文章段落、笔记摘抄都可以，我来帮你提炼。" |
| 检索查询 | 至少一个关键词 | "你想找关于什么主题的笔记？给个关键词。" |

### 文件太多（>200 个）

1. 分批处理，每批 50 个
2. 先按修改时间排序，优先整理「最近修改过的」
3. 同类型的集中处理（如先处理所有 `.md`，再处理 `.txt`）
4. 告知用户预计需要几轮

### 同名文件冲突

1. 比较内容，如果高度相似则合并
2. 内容不同则在文件名后加序号 `{原文件名}-2.md`
3. 列出冲突清单让用户决策

### 二进制文件（PDF/图片/Office 文档）

1. 如果用户提到有截图需要 OCR：推荐 Windows 用户用 PowerToys Text Extractor（Win+Shift+T），Mac 用户用系统自带的 Live Text
2. PDF 文件：直接放在知识库目录中，文件名遵循命名规范，在相关笔记中用相对路径链接
3. 不主动提取 PDF 文字（除非用户明确要求），因为本机提取需要额外工具

### 用户不愿意迁移文件

1. 不强推。改为「索引模式」：在原位置不动，只在知识库中创建索引文件（包含路径 + 标签 + 摘要）
2. 索引文件放在知识库的 `0-收件箱/` 或对应领域文件夹

### 知识库文件已存在同名

1. 不覆盖，询问："同名文件已存在，覆盖还是合并还是换名？"
2. 备选命名：`{原文件名}-v2.md`
